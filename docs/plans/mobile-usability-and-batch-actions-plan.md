# TrguiNG 手机端可用性与批量操作改进计划

## 1. 文档定位

本文档固化手机端以下四项改进的最终方案，作为后续实施、代码评审和验收的权威参考：

1. 手机端底部状态栏改为稳定的两行布局。
2. 手机端所有 Modal、Drawer 等弹层的关闭按钮增大。
3. 种子卡片默认不显示选择框，仅进入选择模式后显示。
4. 补齐并强化手机端多选后的批量操作入口与能力。

本文档基于当前代码状态编写。`docs/plans/mobile-responsive-plan.md` 是早期移动端总体方案，其中关于长按、详情呈现和工具栏结构等部分已被后续实现调整；涉及本次四项改进时，以本文档为准。

## 2. 目标与约束

### 2.1 目标

- 提高手机端状态信息的可读性。
- 将所有关键关闭操作提升到适合触屏的尺寸。
- 保持默认列表简洁，明确区分浏览模式和选择模式。
- 让手机端批量操作能力尽量与 PC 端一致。
- 让用户明确知道“更多”中包含完整批量操作，而不是依赖难以发现的纯省略号图标。

### 2.2 约束

- 桌面端现有布局和交互必须保持不变。
- 响应式断点继续使用 `max-width: 768px`，通过 `useIsMobile()` 判断。
- 不复制 RPC 业务逻辑；手机和桌面复用相同的 action、mutation 和 modal 回调。
- 不引入长按作为主要交互。
- 卡片主体在默认模式下继续打开种子详情。
- 卡片右侧 `...` 继续作为单个种子的操作入口。
- 顶部“选择”按钮继续作为进入多选模式的唯一显式入口。
- 所有可点击目标在手机端应尽量达到约 `44 x 44px` 的触控热区。

- `src/components/statusbar.tsx`
- `src/components/server.tsx`

问题：

- 纯 `...` 不足以表达“完整批量操作入口”。

- 单选专属操作和多选操作的边界不够清楚。

## 4. 最终交互方案

## 4.1 手机端状态栏两行布局

### 4.1.1 布局结构

手机端不再依赖自动 `flex-wrap` 决定布局，而是显式渲染两行：

```text
┌─────────────────────────────────────┐
│ ↓ 63.48 KB/s          ↑ 12.00 KB/s │  第一行：实时速度
├─────────────────────────────────────┤
│ 选中 38.75 GB  完成 140 MB  剩余…   │  第二行：选中统计
│                         [主题][字][i]│  第二行右侧：工具按钮
└─────────────────────────────────────┘
```

推荐实际结构：

- 第一行：下载速度和上传速度各占约一半宽度。
- 第二行：选中统计占剩余宽度，主题/字体/版本按钮固定在右侧。
- 未选择任何种子时，选中统计可以继续显示零值，第一阶段不改变业务语义。
- 桌面端继续使用当前单行状态栏，不受影响。

### 4.1.2 速度文案

第一阶段保留当前速度和限速信息，不改变数据含义：

- `63.48 KB/s (50.00 KB/s)`

若 `390px` 等小屏仍出现拥挤，可在后续细化阶段仅对手机端缩短为：

- 主文本显示当前速度。
- 限速值使用较弱颜色、小号文字或第二视觉层级。

不建议第一阶段直接删除限速信息，以免产生功能信息回退。

### 4.1.3 样式要求

- 两行高度固定、可预测。
- 每个速度单元允许文本省略，但不得覆盖另一侧内容。
- 工具按钮不能挤压第一行速度。
- 状态栏总高度增加后，列表容器必须正确缩小，不得被底栏覆盖。
- 选择模式下的批量操作栏位于状态栏上方，不能与状态栏重叠。

## 4.2 手机端关闭按钮统一放大

### 4.2.1 目标尺寸

- 点击热区目标：约 `44 x 44px`。
- X 图标目标：约 `20-24px`，根据 Mantine CloseButton 的最终视觉效果调整。
- 保持足够 header 内边距，避免按钮贴边。

### 4.2.2 实现层级

优先统一处理，不逐个弹层重复配置：

1. `HkModal`：为手机端 Modal 统一设置 close button 和 header 样式。
2. 移动端 Drawer：通过统一 class 或 Mantine 主题样式覆盖 Drawer close button。
3. 如 Mantine v6 的组件级 styles 无法覆盖所有 Drawer，再建立一个轻量共享样式类。

覆盖范围：

- 设置类 Modal。
- 添加、删除、移动目录、修改 Tracker 等业务 Modal。
- 筛选器 Drawer。
- 种子详情 Drawer。
- 添加种子 Drawer。
- 后续新增的手机端批量操作 Bottom Sheet/Drawer。

### 4.2.3 桌面兼容

- 桌面端保持现有按钮尺寸。
- 样式仅在 `useIsMobile()` 或手机端专属 class 下生效。

## 4.3 默认隐藏选择框

### 4.3.1 默认浏览模式

- 不显示 Checkbox。
- 点击卡片主体打开种子详情。
- 点击卡片右侧 `...` 打开单个种子的操作 Bottom Sheet。
- 点击顶部“选择”进入选择模式。

### 4.3.2 选择模式

- 所有可见卡片显示 Checkbox。
- 点击卡片主体或 Checkbox 都切换该种子的选中状态。
- 顶部替换为“取消 / 已选 N 项 / 全选”。
- 底部显示批量操作栏。
- FAB 隐藏。

### 4.3.3 布局稳定性

默认隐藏 Checkbox 后，需要避免进入选择模式时卡片内容剧烈横向跳动。实施时比较两种方案：

方案 A，推荐：

- 默认不渲染 Checkbox。
- 选择模式出现 Checkbox 时允许标题区域轻微右移。
- 通过短过渡或统一间距降低突兀感。

方案 B，备选：

- 默认保留等宽占位但不显示 Checkbox。
- 选择模式仅替换占位内容。
- 布局最稳定，但默认态会浪费左侧空间。

优先采用方案 A，因为“默认列表简洁、释放标题空间”比完全无位移更重要。

### 4.3.4 状态清理

- 退出选择模式时清空选中集合，沿用当前行为。
- 从手机宽度切换到桌面宽度时清空手机选择模式，沿用当前行为。
- 筛选导致已选种子不可见时，继续通过现有 `filter` reducer 移除不可见选中项。

## 4.4 手机端批量操作栏

### 4.4.1 固定操作栏

保留底部固定操作栏，提供三个最高频动作和一个明确的完整菜单入口：

```text
┌─────────────────────────────────────┐
│  [开始]      [暂停]      [删除]      [⋯ 更多] │
└─────────────────────────────────────┘
```

最终决策：

- “更多”入口必须同时包含图标和文字标签。
- 不再使用只有 `...` 的纯图标入口。
- 推荐图标为 `ThreeDots`，文字为“更多”。
- “更多”按钮应与其他批量按钮拥有接近的触控热区。

### 4.4.2 直接操作

底部固定栏直接提供：

- 开始。
- 暂停。
- 删除。
- 更多。

这些操作在未选中任何种子时禁用，“更多”可选择整体禁用，或打开后所有批量项禁用。推荐整体禁用，减少无效交互。

### 4.4.3 “更多”菜单信息架构

“更多”应采用适合手机端的 Bottom Sheet 风格，并按语义分组。建议最终结构如下：

#### 传输操作

- 重新汇报。
- 重新校验。

#### 队列操作

- 队列上移。
- 队列下移。
- 可选后续扩展：移至队首、移至队尾。

#### 编辑操作

- 修改 Tracker。
- 变更目录。
- 设置标签。

#### 优先级

- 高。
- 正常。
- 低。

#### 详情

- 种子详情，仅选中一项时启用。

### 4.4.4 从批量菜单移出的内容

以下内容不属于选中种子的批量操作，建议不再放入“更多”：

- 添加种子链接。
- 切换备用带宽。
- 应用设置或 Transmission 设置。

它们已有或应保留独立入口：

- 添加种子由 FAB 和添加种子 Drawer 负责。
- 备用带宽与设置属于全局操作，应放在非选择模式的工具入口或设置入口中。

这样可以让“更多”明确等于“对当前所选种子执行更多操作”。

### 4.4.5 单选与多选规则

| 操作 | 单选 | 多选 | 说明 |
|------|------|------|------|
| 开始 | 支持 | 支持 | 复用 `torrent-start` |
| 暂停 | 支持 | 支持 | 复用 `torrent-stop` |
| 删除 | 支持 | 支持 | 复用删除 Modal |
| 重新汇报 | 支持 | 支持 | 复用 `torrent-reannounce` |
| 重新校验 | 支持 | 支持 | 复用 `torrent-verify` |
| 队列上移 | 支持 | 支持 | 复用现有 action |
| 队列下移 | 支持 | 支持 | 复用现有 action |
| 变更目录 | 支持 | 支持 | 复用现有 move Modal |
| 设置标签 | 支持 | 支持 | 复用现有 labels Modal |
| 优先级 | 支持 | 支持 | 复用 `useMutateTorrent` |
| 种子详情 | 支持 | 不支持 | 多选时禁用 |
| 修改 Tracker | 待按 PC 语义确认 | 待按 PC 语义确认 | 实施前核对现有 Modal 是否支持多个 ID |

修改 Tracker 是唯一需要在实施前确认业务语义的操作：

- 如果现有 PC 端 Modal 已支持多个选中 ID，则手机端直接复用。
- 如果现有实现仅支持当前单个种子，则多选时禁用，并在菜单文案或提示中说明“仅支持单个种子”。
- 不在手机端另造一套与 PC 不同的 Tracker 批量修改规则。

### 4.4.6 菜单关闭与反馈

- 点击可执行项目后关闭 Bottom Sheet。
- RPC action 成功后沿用现有绿色通知。
- RPC action 失败后沿用现有红色通知，并保留具体错误文本。
- 打开业务 Modal 时先关闭“更多”Bottom Sheet，避免叠层冲突。
- 删除、变更目录、修改 Tracker 等操作完成后，选择模式是否退出由各操作语义决定：
  - 删除成功后退出选择模式并清空选中。
  - 编辑类操作完成后可保留选择模式，方便继续批量操作。
  - 第一版可维持当前选择状态，除非种子已被删除。

## 5. 代码组织建议

### 5.1 复用 action handler

当前 `useButtonHandlers()` 已提供开始、暂停、删除、队列移动、变更目录、标签和优先级等能力。实施时应扩展并复用该层，而不是在手机菜单内直接重复 mutation 逻辑。

建议补充的 handler：

- `reannounce` -> `torrent-reannounce`。
- `verify` -> `torrent-verify`。
- `editTrackers` -> 复用 `modals.current` 中对应回调。

如 PC 的右键菜单已有完整 action 定义，可进一步抽取共享的 action 描述，但应遵循最小改动原则：只有在能够明显减少手机/桌面重复菜单逻辑时才抽取。

### 5.2 手机批量菜单组件边界

若 `MobileToolbar` 继续增长，建议把批量操作栏提取为同文件内的私有组件，例如：

- `MobileSelectionToolbar`
- `MobileBatchActions`

第一版优先保持在 `toolbar.tsx` 内，不新建跨文件模块，除非实现后组件明显过长或需要复用。

### 5.3 样式位置

- 状态栏布局优先使用组件内 Mantine props / `sx`，必要时增加语义 class。
- Drawer/Modal 的手机关闭按钮优先通过共享封装或主题配置处理。
- 与手机种子卡片、底部批量操作栏相关的样式继续放在 `src/css/torrenttable.css`。
- 避免影响桌面端 `.statusbar`、Modal 和表格样式。

## 6. 分阶段实施计划

## Phase 1：状态栏两行化

### 目标

先解决手机端底部状态信息拥挤问题，不改变批量操作逻辑。

### 预计修改文件

- `src/components/statusbar.tsx`
- 必要时 `src/components/server.tsx`
- 必要时 `src/css/custom.css`

### 实施步骤

1. 为手机端建立显式两行 DOM 结构。
2. 第一行只渲染下载和上传速度。
3. 第二行渲染选中统计和工具按钮。
4. 桌面端继续沿用当前结构。
5. 检查状态栏增高后列表、FAB 和批量操作栏的 bottom offset。

### 验收标准

- [ ] `390 x 844` 下下载和上传速度稳定显示在第一行。
- [ ] 选中统计和工具按钮稳定显示在第二行。
- [ ] 文本不互相覆盖。
- [ ] 状态栏不遮挡种子列表。
- [ ] 桌面端状态栏无布局变化。

## Phase 2：关闭按钮触控优化

### 目标

统一提升所有手机端弹层关闭按钮的可见性和可点击性。

### 预计修改文件

- `src/components/modals/common.tsx`
- `src/components/server.tsx`
- `src/components/toolbar.tsx`
- 可能涉及 Mantine theme 或共享 CSS

### 实施步骤

1. 在 `HkModal` 中统一设置手机端 close button 样式。
2. 为手机端 Drawer 统一增加 close button 样式。
3. 确保点击热区约为 `44 x 44px`。
4. 检查 header 高度、标题对齐和内容可视高度。

### 验收标准

- [ ] 设置、删除、移动目录等 Modal 的 X 明显增大。
- [ ] 筛选、详情、添加种子 Drawer 的 X 明显增大。
- [ ] 所有关闭按钮可以单手稳定点击。
- [ ] 桌面端按钮尺寸不变。

## Phase 3：选择模式视觉收敛

### 目标

默认隐藏选择框，强化浏览模式与选择模式的区别。

### 预计修改文件

- `src/components/tables/torrentcard.tsx`
- `src/components/toolbar.tsx`
- `src/css/torrenttable.css`

### 实施步骤

1. 默认模式不渲染 Checkbox。
2. 点击顶部“选择”后显示所有 Checkbox。
3. 选择模式下卡片主体和 Checkbox 均可切换选中状态。
4. 检查进入/退出选择模式时标题和状态图标的位置变化。
5. 保持默认卡片主体打开详情、右侧 `...` 打开单项操作。

### 验收标准

- [ ] 默认列表无 Checkbox。
- [ ] 点击“选择”后 Checkbox 出现。
- [ ] 可连续选择多个种子，不清除之前选择。
- [ ] 点击“取消”后 Checkbox 消失且选择被清空。
- [ ] 默认模式点击卡片仍打开详情。
- [ ] 右侧单项 `...` 行为不变。

## Phase 4：批量操作入口重构

### 目标

让多选后的操作入口明确可见，并清理菜单语义。

### 预计修改文件

- `src/components/toolbar.tsx`
- 必要时 `src/components/contextmenu.tsx`

1. 保留开始、暂停、删除三个直接操作。

5. 添加清晰的分组标题或 Divider。

### 验收标准

- [ ] 用户无需猜测即可看到“更多”入口。
- [ ] “更多”入口图标和文字都清晰可见。
- [ ] Bottom Sheet 可在小屏滚动。
- [ ] 菜单只包含当前选中种子的相关操作。
- [ ] 未选择种子时批量操作不可执行。

## Phase 5：批量能力补齐

### 目标

## 8. 实施顺序与提交建议

推荐按 Phase 单独实施和验证，避免一次改动过大：

1. 状态栏两行化。
2. 关闭按钮触控优化。
3. 默认隐藏选择框。
4. “更多”入口与菜单结构调整。
5. 批量操作能力补齐。
6. 综合回归与细节打磨。

如果需要提交 Git，建议每个 Phase 独立提交。不要把状态栏、弹层样式和批量业务能力塞入同一个提交，以便出现回归时快速定位。

## 9. 最终决策摘要

- 手机状态栏使用明确的两行布局，不依赖自然换行。
- 第一行显示下载和上传速度。
- 第二行显示选中统计和主题/字体/版本按钮。
- 手机端 Modal 和 Drawer 的关闭点击热区统一提升到约 `44 x 44px`。
- 默认浏览模式不显示 Checkbox。
- 点击顶部“选择”后进入显式多选模式并显示 Checkbox。
- 多选底部栏保留开始、暂停、删除三个高频动作。
- 完整批量菜单入口采用 `ThreeDots` 图标加“更多”文字标签。
- “更多”菜单仅包含针对当前选中种子的操作。
- 补齐重新汇报、重新校验、修改 Tracker、变更目录、设置标签和优先级等能力。
- 种子详情仅单选时启用。
- 修改 Tracker 的多选语义必须与 PC 端现有行为保持一致。
- 桌面端现有布局、快捷键、表格选择和右键菜单保持不变。
